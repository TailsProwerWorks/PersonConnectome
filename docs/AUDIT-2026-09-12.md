# PersonConnectome polish audit — 2026-09-12

## Result

Implemented and verified offline, then deployed to the discovered local PersonConnectome mod folder; all 15 deployed file hashes match their sources. Changes are not committed or published. No agent-driven native game render, physics session or mod-loader acceptance run was performed. User screenshots confirm the earlier Canvas overlay renders; the new interactions and motor defaults still require native acceptance. The repository was clean at the start. The authoritative RuntimeBrain architecture and pinned connectome payload/carrier were preserved.

Native rendering and rejection-enabled loading remain separate acceptance checks.

- Wetness, underwater state and global `IsCapable` do not mark every limb incapable. Local failure and terminal native health/brain state remain separate.
- Brain damage and unconsciousness are nonterminal. Invalid health suspends control without inventing death.
- Vision remains nearest-collider line of sight times ambient light; audio remains external physical-object playback. Motion/contact channels are derived mechanical proxies. No semantic retina, smell, human-brain anatomy or biological swimming is claimed.
- Existing restorative chemistry is an engineered sensory-derived intervention, not proven neural healing. No new networking, shell execution, forces, damage injection, liquid injection or unsafe game manipulation was added.

## Shady Code Rejection

The [official rules](https://wiki.studiominus.nl/details/shadyCodeRejection.html) were fetched and read. `scripts/Test-ModSourceSafety.ps1` uses PowerShell 7's bundled Roslyn parser to check the actual 10 manifest scripts for forbidden identifiers, escaped identifier forms, extern, forbidden namespace imports and aliases. Comments/strings are not falsely treated as identifiers. The guard includes positive and negative self-tests.

**All 11 current sources pass the documented-rule check.** No rejection setting is modified. This is an offline source check, not proof that the native mod compiler/loader accepts the package with rejection enabled. That final test remains required.

The follow-up `Test-GameCompilation.ps1` additionally runs the installed compiler's own `ScanUtils.ScanTreeLowRisk` and `ScanUtils.ScanTreeHighRisk` on every source semantic model after exact-reference compilation. Both scanners accept all 11 current sources. The compiler server and full loader are not invoked; scanner rejection or unavailable APIs fail the preflight.

## Manual acceptance and remaining limitations

Run the [manual checklist](manual-game-test.md) inside People Playground, including rejection-enabled loading; 800×600 through 4K plus resizing/text scales; world lighting/effects and camera changes; scrolling/collapse/person selection; UI clicks versus world interaction; map/spike capture coherence; movement under water/injury/death; and one/multiple-person frame times.

Native `PersonBehaviour` decays walking requests and selects poses. Native `LimbBehaviour` can apply pose motors and upright torque. The mod originates its submitted requests but **does not exclusively control standing, balance or all actual motion**. Those native mechanics were not disabled. Effective walking/swimming and perceived responsiveness require game testing.

The map omits unavailable positions and most located neurons from its display sample; the entire graph still runs. Captures can miss inter-capture spikes; counts are engineering neural ticks, not validated biological Hz. Acid contact is measured at the status anchor and can miss another limb touching acid. The existing overlap buffer is limited to 128 hits. Unknown/missing source data and conservative Root/Root filtering can miss genuine signals. Save/load persistence is unverified. Direct builds retain the existing generic Steam default unless `PeoplePlaygroundInstall` is provided.

Native torque/pose mechanics remain active.
- Native adrenaline decays at 1 unit/sec within a 0..20 range. Inspected injury paths do not establish a required surge. Display raw adrenaline separately from its clamped neural signal. The final scheduler skips inputs that cannot survive refractory timing, avoids self-requeue after firing, and removes same-tick queued deliveries by iterating only fired IDs. No reliable general CPU speedup is claimed. Freed slots change overloaded dynamics, so these are matched inputs rather than identical spike trajectories. Heavy input still reaches the 24,000 eligible-neuron limit; OVERLOADED remains truthful and does not imply measured frame-time overload.
