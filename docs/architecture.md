# Architecture

`src/Core/LifBrain.cs` is the single authoritative brain implementation. The game and runtime tests compile that same physical source. The source tree is intentionally layered:

* `src/Core/` contains the validated asset contract, texture-carrier/FLYB decoder, `SensoryFrame`, `MotorCommand`, `IBodySensor`, `IBodyActuator`, and the LIF engine.
* `src/Adapters/` contains People Playground sensing/actuation, collision probes, liquid/status readers, and the disabled `PeoplePlaygroundFlyAdapter` capability stub until the native fly API is verified.
* `src/UI/` contains optional status display, brain-map diagnostics, telemetry layout, and manual input state.
* `src/Mod/` contains only mod registration and lifecycle/timing wiring.

`src/Mod/ModRegistration.cs` registers the Human variation and creates a brain only after the game-specific asset loader validates the payload. No alternate/demo graph is substituted; Core owns graph decoding while Adapters own game-body integration.

The shared immutable asset is a thresholded MaleCNS v1.0 derivative: 176,422 neurons and 6,287,749 connections retained at weight ≥5, excluding self-edges. The PNG carries the exact compressed FLYB bytes. Mod verifies compressed SHA-256, dataset/version, counts, CSR monotonicity, targets and used metadata indexes. Each person has independent dynamic neural state. The scalar reader reuses an eight-byte buffer instead of allocating an array for every neuron/edge scalar; variable-length reads still own their arrays and truncated reads still fail.

Each control tick reconciles tracked limbs and samples a fresh bounded frame. Native measurements are normalized; validity is tracked for health, oxygen, consciousness, circulation, damage, minimum limb health and blood deficit. Missing/nonfinite readings do not become positive deficit signals. Damage uses valid connected-limb health samples only, with a separate explicit-loss denominator for limb loss. The legacy Vitality field now reports the minimum valid normalized health of connected limbs, labeled min-limb-health. Known detached limbs remain excluded from body sensing and actuation while their liquid identities remain available to diagnostics; they are also excluded from own collision, nearby and audio signals. Foot-floor impacts are still contact, including self-generated movement.

Vision is a head-relative frontal-field line-of-sight/combined-light proxy; [head-relative-vision.md](head-relative-vision.md) specifies its 16-candidate bound and orientation convention. Light combines native ambient grayscale and the strongest supported nearby light-sprite footprint estimate; see [local-light-sensing.md](local-light-sensing.md). Audio is active external physical-object playback with own-source and Root/Root filtering. Vibration and legacy body proprioception are derived mechanical channels. Connected native hinge angles/speeds supply the new joint encoders; signed anchor velocity and tilt are separately labeled. Falling reads downward native limb velocity with floor-contact gating. Ambient temperature comes from the native grid; nearby dynamic objects and lava add attenuated thermal cues. Static geometry does not create cold signals. Acid-pool exposure requires contact at the status anchor (within 0.05 world units), a limited proxy that can miss acid touching another limb. None of these channels establishes semantic perception or a biological sensory model.

Connected, readable limb health is sampled against its previous valid baseline. The largest positive normalized drop becomes one DamageEvent; persistent damage is a separate diagnostic. Changes to InitialHealth, invalid/lost/disconnected samples, suspension and terminal state clear/re-prime history. A fatal limb transition can emit once while the person remains nonterminal. The injury encoder uses a saturating Hill-derived gain, explicitly separate from native Pain. Regional contact maps recognized human roles to disjoint fly bristle/tactile groups using existing nerve annotations; broad impact and injury merge by maximum rather than stimulating a neuron twice. See the exact formulas and anatomical limitations in sensory-mapping.md.

Up to five nearest-visible colliders in separate head-relative angular bands, selected from the 16 closest in-field candidates, supply 2D bounds-radius and rigidbody-relative-motion estimates. Value-type observations preserve frame snapshots without mutable array aliasing. Each visual feature is pooled by maximum separately for L/R neural inputs, then passed through the existing manual resolver once per channel. Sweep subtracts measured head angular velocity; this is not a rendered retinal image. One reusable 512-bin spectrum buffer samples only the strongest accepted external AudioSource once per read. Squared non-DC amplitudes give below/above-100 Hz energy fractions scaled by current playback strength. Invalid/empty spectra retain the broad playback proxy; last-heard history is never input. This is Unity source analysis with startup history and coarse resolution, not biological hearing or guaranteed low latency.

Liquid sensing enumerates each tracked circulation's `LiquidDistribution` every control tick. Finite positive amounts are normalized by a finite positive `TotalLiquidAmount`; invalid entries contribute no exposure. A cleared, reused dictionary retains the largest current per-ID fraction across tracked limbs for the Senses page, never a cumulative dose or stale history. Exact case-sensitive IDs from the inspected stock registry select engineered exposure routes. Unregistered display names are text only. Non-blood liquids, including unknown and unusual serums, populate `LiquidExposure` telemetry. They no longer stimulate an invented neural receptor route. Recognized sedative/stimulant/restorative categories retain existing engineered decoder adjustments; native effects are observed separately. `LiquidWater` is reserved and zero for stock circulation because no plain water ID is registered. `Infection` is the legacy internal field for native `IsZombie`, now labeled `zombie(native)`; it is not inferred from a reanimation agent. Reading liquids does not inject them or enact their native syringe effects. See the exact coverage in api-compatibility.md.

The sensory router drives real populations selected by MaleCNS type/class/subclass/superclass/nerve metadata. See [sensory-mapping.md](sensory-mapping.md) for exact selectors, directions, reference sources and intentional unmapped fields. It no longer paints internal injury/chemistry onto photoreceptors or directly stimulates locomotor descending neurons. All eligible members are considered, replacing a biased first-N input cutoff. Sparse LIF processing first integrates every eligible active neuron exactly once with the existing signed accumulation, decay, clamp and threshold. Cells below threshold retain their state; no input update is dropped to save a propagation slot. The expensive outgoing-edge phase propagates at most 24,000 threshold crossings per tick. Only excess crossings require sorting/fair selection, with current sensory candidates prioritized. Unselected crossings are reset and reported as dropped-spikes instead of being deferred; newly arriving next-tick input to those cells remains eligible. `integrated` counts nonzero incoming-input updates; `decay-only` counts updates with no net input; `fired` counts propagated spikes against the 24,000 cap. `STEADY`/`OVERLOADED` refer to actual discarded crossings, not CPU time. The active set remains bounded by the graph's neuron count. Spike count does not bound outgoing edges or wall-clock cost. Refractory cells are skipped, arrival on the exact recovery tick remains valid, and post-fire cleanup removes only actually fired IDs from next-tick queues. Compared with the old 24,000-integration cap, more state and activity survive; this intentionally changes previously truncated traces. See [measurements and limits](scheduler-performance.md).

`ManualInputState` is session-local state owned by each controller. `LifBrain` resolves it after the native frame has been encoded and immediately before the existing population injection path. Mixed mode replaces only selected routes; Manual only zeroes unselected external routes without clearing recurrent state, potentials, refractory timers or pending synaptic work. The resolver also owns finite normalized values, normalized population-side direction, bounded neural-tick pulses and latest live/effective readings. Manual feature routes are visited even when their natural observations are absent. The original `SensoryFrame` remains authoritative for telemetry, lifecycle, movement permission and decoder constraints.

Motor decoding starts with the fly's reference channels: forward, yaw, backward, halt, brake, jump, takeoff, landing, flight power/yaw, wing motor, grooming, feed, courtship, song and leg-motor activity. The Overview page reports these channels directly as normalized decoder requests. Forward/backward and leg channels use 150 ms exponential filters; lateral DNa02/DNg13/DNa01 activity uses a 100 ms filter. The existing human body receives a separate, explicitly labeled adaptation of the locomotor subset; it does not redefine the fly channels. A forward mode enters at filtered 0.08 and exits below 0.04 after a 250 ms minimum dwell. Raw MDN fraction >=0.5 preempts forward with backward mode, which exits below filtered 0.25 after its minimum dwell. Active modes use a 0.3 neural walk floor; the adapter applies a 0.55 final walk floor after modifiers so default gain 2 clears the native 0.5 walking gate with decay margin. These are engineering decoder settings, not neural rates or guaranteed gait. MN9 proboscis activity is reported as `feed`, not human grasping; brain grip requests remain zero and therefore neutral while active. Hazard does not directly choose an escape direction and water does not start an independent oscillator. Neural halt/brake clears human adaptation requests immediately; fly channels remain available for diagnostics. Other human motor/grip requests are rate limited to eight normalized units per elapsed game second, with at most 0.25 seconds used by each smoothing step. Terminal/invalid health and unavailable/low consciousness clear motor output immediately; terminal state also clears neural state, while invalid health preserves neural state for later recovery. Nonterminal unconsciousness can still be sampled neurally. Restorative requests remain engineered, sensory-derived interventions, not proven neural healing.

The adapter submits walking, joint and optional grip requests through native APIs with local limb eligibility. Explicit conversion defaults are a walking gain of 2 (then -1..1 clamping) and a 30 deg/s full-scale joint target; the component exposes bounded overrides. These are engineering choices, not native-game calibration. Retained last-heard audio text and its real-time timestamp are display history only; they never contribute to sensory sound input. **Native locomotion mechanics are still involved.** Inspected `PersonBehaviour.Update` decays walking requests; `LateUpdate` selects a pose. The controller's `[DefaultExecutionOrder(-1000)]` refreshes its cached permitted walking intent after that decay and before the inspected default-order native `LateUpdate`; full neural application remains tick-rate controlled. `LimbBehaviour.ManagedFixedUpdate` can run `ApplyPoseOverrides`, `MoveIntoPose` and `FakeStandUpright`; the latter applies native torque using `FakeUprightForce`. Direct fly control is enabled by default and suppresses the verified limb and pose-level upright/stumble assists while enabled, restoring captured values on disable; pose selection, joints, gravity and collisions remain active. No claim of exclusive neural standing/balance control is made.

Threat decoding distinguishes raw `DNp01-fired` from the context-qualified `escape-request`. Recurrent activity can fire DNp01 without an observed threat, so raw firing alone no longer activates the avoidance modifier or overview escape flash. A spike qualifies only while movement is permitted and evidence occurred within 0.5 game seconds: normalized native body-hazard sum >0.5, a sampled DamageEvent >0.001, or effective LC4/LPLC2 input >0.05. The visual value follows manual overrides, including manual-only suppression and explicit visual stimulation. Native hazard safety remains independent. Existing 1.5-second cooldown and 0.25-second quiet rearm are preserved; invalid/terminal/suspended control clears context. Actual elapsed game time expires context even across a long callback gap. The 0.35-second overview flash represents an accepted request. This is an explicit Human gameplay decoder rule, not neural causal tracing or biological validation; looming can legitimately qualify before damage.

The controller preserves fractional tick time, so a 20 Hz request works over 50 Hz physics callbacks. At most one neural step runs per callback; excess whole intervals are dropped without catch-up. Actual elapsed game time is passed to motor smoothing. Diagnostics record control-loop milliseconds, input age in unscaled time and dropped game time. Simulation time follows game callbacks, not continuous biological time.

`UI/BrainMap.cs` retains every finite soma position with its original neuron index and superclass category. The full graph remains simulated. The map data is shared with the immutable asset; there is no per-frame graph scan. The screen display projects raw X/Z coordinates with a common scale, labels the projection without inventing anatomical orientation, and marks actual fired IDs in a captured tick. All positions are rasterized into a 256 x 320 texture, so nearby points can share pixels and zoom enlarges the existing raster. It normally uploads that texture at most ten times per second of unscaled UI time (direct resizing can refresh it sooner) while the Brain page is selected, and only for a new captured tick. Map buffers are released on deselection or leaving the Brain page. Formatted UI text and render snapshots are cached at this refresh interval. Whole-graph spike history records every processed tick, including ticks between captures; population bars show captured fired/member counts, not Hz.

The Canvas/TextMeshPro display is one opaque top-center screen overlay for a selectable person. The pure TelemetryLayout helper bounds its scale and dimensions, reserves side space for game controls and keeps collapse anchored in place. A separate auto-hiding scrollbar shows reading position without covering content. The title bar drags the panel; the lower-right handle resizes it down to 360 by 300 logical units. Position is clamped to keep the header and handle reachable. Size and position are session-only and shared across the selected-person panel. It does not inherit world position, camera orientation, scene depth or lighting. Overview, Senses and Brain pages wrap text and scroll; text-size controls and collapse preserve screen space. A number stable while registered and world coordinates identify the selected person. TelemetryIdentityPool assigns the lowest unused positive number on activation and releases it on disable/disposal, including deletion and Undo. Surviving people are not renumbered; repeated disable/destroy calls cannot release another person's reassigned number. Construction alone consumes no number, and an empty registry starts again at 1. The controlled count still uses the active display list. The controller owns registration and texture disposal. Disable invalidates the adapter sample and clears display history/timing; re-enable waits for a fresh tick. Ordinary person selection preserves history. No game persistence is implemented. Offline doubles and source checks do not replace native UI/physics/loading/performance acceptance.

Body threat and neural escape remain visible in adjacent header columns, with independent clear/idle/requested states and colors. The native signal and manual-input indicator remain below them; the columns never replace each other.

### Food cues, escape locomotion and blood reporting

The existing bounded nearby scan now matches the original stock Pumpkin catalog asset, supplying explicit proximity and native head-contact gameplay cues through `ManualInputCatalog` and the single `LifBrain`. Selected real ORN and labellar populations receive these inputs; item names never select motors. Ordinary objects retain geometry/contact/temperature/audio/light routes. No native smell/taste assay or nutrition model is asserted.

Qualified DNp01 events translate to a short native walking burst, independent of whether ordinary walking populations are currently idle. A 0.6-second timer uses elapsed game time; neural backward intent determines negative direction, otherwise the native forward convention applies. Existing motor smoothing, native bounds, limb-local capability and immediate stop gates remain. This is a Human actuator policy, not shooter localization or a reconstructed fly escape.

Blood-specific native amounts are reported as connected-limb min/max with valid/expected sample counts, separately from the maximum relative deficit since each observed peak. The first positive sample cannot establish blood lost before tracking; an initially empty circulation has known raw zero but unknown relative deficit. Tiny positive quantities remain valid. Null/invalid liquid data stays unavailable. See [implementation evidence](food-escape-blood.md).

Object-audio follow-up: the bounded nearby scan includes the native jukebox music source and attached AudioSources, beyond MainAudioSource. Up to 64 unique sources are evaluated; partial scans are labeled. Playback/mute/ownership filters and strongest-source spectrum/direction remain. This is a playback proxy, not sound pressure or music understanding. See [checks](food-escape-blood.md).
