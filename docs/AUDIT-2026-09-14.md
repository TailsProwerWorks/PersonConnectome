## Concrete defects and fixes

- Limb health normalization incorrectly used max(1, InitialHealth). Healthy custom limbs with InitialHealth below one could appear damaged. Normalization now uses the actual finite positive baseline, clamps over-baseline health before division and retains one-shot injury sampling.
- Negative native blood amounts could look like total blood loss. They now remain unknown and do not overwrite the learned baseline.
- Missing circulation prevented valid connected-body sensing but still allowed local motor output. It now excludes only that limb with unknown-circulation; healthy limbs keep their commands.
- Native LimbBehaviour.Vitality was mixed with a health fallback. Installed ActOnImpact IL uses Vitality in impact susceptibility and internal-bleeding scaling, not as remaining health. The diagnostic now explicitly reports minimum valid normalized connected-limb health. Legacy field names remain internal to avoid an unrelated rename.
- Two status separators contained invalid UTF-8 bytes. All panel/stimulation separators now use ASCII vertical bars; source validation strictly rejects invalid UTF-8 and regression-checks the problematic separator. Uniformly duplicated blank lines in the display source were removed without changing code.
- A small measured injury could qualify escape while rounding to zero in telemetry. Injury events now appear in THREAT SOURCES and the body readout with four decimal places. The measured threshold was retained; no injury is fabricated or artificially enlarged.
- Suspended manual input retained a stale positive EFFECTIVE reading. Deactivation now clears sampled readings while preserving configured values/selections and cancelling pulses.
- Native-pose menu filtering matched unrelated descriptions containing protection/resting/sitting. Description fallback now requires animation-override wording, while exact native identities remain supported. The installed compiler also exposed an inaccurate test double: ContextMenuButton is a native value type. The double now matches that and tests preserve default/benign entries.
- Mod sums previously allowed a nonfinite channel to erase another valid hazard, freeze, healing or contact signal. Terms are sanitized independently before aggregation. This hardens the runtime boundary; the current native adapter already sanitizes these inputs.

The preceding escape/UI changes were retained: raw DNp01 firing is separate from a context-qualified escape request; body threat and neural escape occupy independent adjacent columns. Evidence may precede injury (looming), and temporal qualification does not establish a biological cause for a spike.
